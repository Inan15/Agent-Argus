## 2. What Went Well (Successes)

1. **The honest-degradation principle held and was verified non-bypassable — APAA's defining promise for
   this epic.** Under budget exhaustion APAA structurally cannot fabricate readiness: the remainder is graded
   `SKIPPED` through the EXISTING `grade_entry` (claim_present=False), the halted branch runs detectors ONLY
   over the assessed set and grades the DISJOINT remainder `SKIPPED` (disjointness structural + e2e-asserted),
   and the partial ledger drives the deep-% down through the REAL frozen 1.6 gate. The floor (3.3) then
   guarantees `INSUFFICIENT_COVERAGE`/exit 3 below 20% — "the limitation is owned by APAA, not blamed on the
   repo." This is the trust property the whole epic exists to deliver, and it was built by REUSING the
   existing grading/gate machinery rather than adding a degraded-mode fork.

2. **Reuse-not-fork held at every cost-governance seam.** 3.1's `ceiling_reached` IS the imported
   `BudgetGuardrails.evaluate_worker_spend` `>=`-is-a-breach decision (asserted live + parametrized across
   `{0,50,99,100,101,500}` incl. the at-ceiling boundary) — no parallel comparison, the policy's internal
   float never escapes `_coerce_breach`. 3.2's `would_breach`/`project_halt_point` delegate to that same
   imported `_coerce_breach`; 3.3's floor READS `verdict.deep_ratio` + `INSUFFICIENT_COVERAGE_FLOOR` (no
   re-derive); 3.4 reuses the 1-3 reader / 3-2 halt / 1.2 ledger / 1.6 gate / 3-1 budget / 3-3 floor all BY
   IMPORT. The frozen 1.1/1.2/1.6 contracts show no working-tree diff across the epic.

3. **The determinism / single-serializer / Fraction-not-float / advisory-moat discipline held across all
   five stories with zero erosion — now across THREE epics.** Ratios stayed exact `Fraction` (3.1 baseline,
   3.3 whole-% via exact-Fraction truncation `int(ratio*100)` — never a float leaf, the serializer genuinely

## 3. Challenges & Growth Areas

1. **The epic's only review FAIL (3.4) was a `[High]` correctness bug that the dev's own keystone test FAILED
   TO CATCH because the fixture masked it — the single most important lesson of this epic.** Resume carried
   forward ONLY `audited_deep`, silently dropping prior assessed-but-non-deep coverage (`audited_shallow` test
   files / `tool_scanned_only` / assessed-`skipped`). This would flip the verdict at the 20% floor: a
   reproduced `halt(6)→resume(100)` yielded `deep_ratio 2/3` vs an uninterrupted `run(100)` of `1/2` — verdict
   + ledger + halt-report bytes diverged. **The 642-green keystone test masked it**: its `vacuous_basic`
   fixture file always sorted into the `skipped` remainder, so the assessed prefix happened to contain only
   `audited_deep` entries — the exact coverage the buggy code did carry forward. A green keystone test that
   structurally cannot exercise its keystone bug is worse than no test, because it advertises a guarantee it
   does not provide.
   - **What caught it:** the reviewer reproduced the divergence directly (not by re-running the dev's test),
     then reverted the fix and confirmed the new RED fixtures (`TC-PIPELINE-001-30` resumed `deep_ratio 1/3≠1/2`
     + `TC-COST-001-132` `carried_forward_paths ()≠('a_test.py',)`) failed on the old behavior and passed on
     the fix — RED-then-green on the *actual* divergence, plus a halt-report-bytes comparison.
   - **Root-cause class:** a keystone fixture whose data distribution does not span the very state the
     keystone assertion is meant to protect (here: an assessed prefix with no non-deep entry). The byte-
     identity assertion was correct; the *fixture* was too weak to make it bite.

2. **Two transport-timeout / session-limit interruptions mid-story (3.4) left the tree broken — and the

   that *looks* further along than it is — reinforcing the still-open AI-E2-1 pre-`review` test-existence guard.

3. **The defer register is STILL split across two homes (AI-E1-3 / AI-E2-3 only partially done — now three

## 4. Key Insights

- **A keystone test must be adversarially fixtured against its OWN keystone failure mode — a green keystone
  test is not evidence until you have seen it go RED on the bug it guards.** The 3.4 FAIL is the sharpest
  instance of this in APAA: the byte-identity *assertion* was right, but the *fixture* never put a non-deep
  entry in the assessed prefix, so the assertion could never observe the drop. The reviewer's discipline —
  reproduce the divergence independently, then revert the fix to confirm RED-then-green on the real
  divergence — is the practice that distinguishes a test that *passes* from a test that *protects*. This
  generalizes a rule worth promoting: for any "X is byte/behaviorally identical to Y" keystone, the fixture
  MUST contain at least one element of every class the equivalence is supposed to preserve, and the test MUST
  be demonstrated RED against a deliberate violation before it is trusted.
- **Reproduce-then-revert (RED-then-green on the actual divergence) is the reviewer practice that catches a
  too-weak keystone test.** No static review of the green test would have surfaced the masked bug — only an
  independent reproduction of the divergence did. This is the human-in-the-review backstop that the rule-of-
  three guard-promotion policy (§9.2) exists to eventually mechanize, but until a guard exists, the
  reproduce-then-revert habit is the control.
- **Resumability is a process property as much as a product property.** Epic 3 shipped FR31 (resume the audit
  from disk) AND demonstrated the dev-loop ITSELF resuming cleanly from a transport-timeout that left a broken
  tree. The same content-addressed on-disk-state discipline that makes the product resumable made the
  workflow resumable.
- **A prior retro's marquee action item, sustained for two epics, compounds.** AI-E1-1 went from "write a
  non-ASCII fixture" (Epic 1) → "apply it at the impure-shell boundary" (Epic 2, prevented a recurrence) →
  "promote it to a standing cross-environment determinism property suite" (Epic 3). The investment is now
  structural, not a per-story chore.
- **Verify-and-lock stories are low-risk BUT can still surface a real bug — the risk is in the seam, not the
  net-new code.** 3.3 and 3.5 were verify-and-lock (near-zero product-code edit), and both passed iter-1. The
  one FAIL (3.4) was a genuinely net-new mechanism (resume) — consistent with the pattern that risk
  concentrates where new behavior reconciles with existing state.
