**Goal achievement.** Epic 5's defining goal — *the same repo at the same commit yields a byte-identical
verdict every time — reproducibility as a system property — with a cache that cannot ossify a wrong answer* —
is **met across all three stories**. The reproducibility floor was delivered as a structural, proven-non-bypassable
property, not an assumption that the LLM repeats itself:

- **The memo cache is provably an OPTIMIZATION that can never change the verdict.** 5.2's keystone is
  HIT==MISS byte-identity (a served hit reconstructs to canonical bytes byte-identical to a cold recompute;
  cold-vs-warm verdict/ledger are identical), and "correct even if the cache is wiped" is asserted directly.
- **The cache cannot ossify a wrong answer (AR6).** 5.3 delivers the asymmetric invalidation contract:
  over-bust is SAFE (recompute is byte-identical to cold per 5.2 HIT==MISS) and under-bust is FORBIDDEN
  (re-serving a stale rejected 🔴 is the precise failure to prevent), each demonstrated RED-then-green. A
  human-rejected finding busts its own cache key; a detector-set change invalidates affected entries.
- **Tamper → MISS, never poison.** 5.2 reuses the 1.3 `read_envelope(verify_hash=True)` tamper guard but
  SWALLOWS a NAMED typed set into a MISS (the ONE place a store error is swallowed vs 1.3 which raises);
  a poisoned entry re-derives the CORRECT result — reproducibility ≠ correctness, mechanized.

**FR/NFR coverage (Epic-5 slice).** FR27 (reproducible verdict via memoization) delivered; NFR-D1 (same repo

## 2. What Went Well (Successes)

1. **The reproducibility floor was delivered as a STRUCTURAL property, not an assumption — the project's
   core promise is now mechanically enforced.** The brainstorm's keystone framing ("NOT an assumption the
   LLM repeats itself — local content-addressed memoization") is realized end-to-end: the cache key folds
   the FULL recording-producing closure (5.1), a hit is byte-identical to a recompute (5.2 HIT==MISS), and
   a wrong answer cannot ossify (5.3 over-bust-safe/under-bust-forbidden). Each leg was demonstrated RED
   against a naive/mutating implementation before being trusted.

2. **The AI-E4-1 no-crash-keystone input-shape checklist (the headline Epic-4 action item) was APPLIED
   PROACTIVELY to the new cache filesystem shell — exactly the surface that produced the 4.2 FAIL — and
   there was no recurrence.** 5.2's cache I/O and 5.3's seam read both enumerate the full failure-input
   matrix (corrupt-bytes / non-UTF-8 / tampered / wrong-schema(`extra=forbid`) / non-file / permission-denied
   / missing) and degrade to a MISS or a typed `BustOutcome`/safe-skip, NEVER raise — a NAMED typed swallow
   set, no bare `except`, each leg RED-first. The "too-weak keystone test" class that FAILed in BOTH Epic 3
   (3.4) and Epic 4 (4.2) did NOT recur in Epic 5's new impure shells. This is the L1-E11 loop working: the
   prior retro's marquee corrective, applied as written to the predicted-risk surface, prevented the
   predicted FAIL.

3. **The keystone-adequacy discipline (AI-E3-1 / AI-E4-1) paid off at the DESIGN level, not just the test
   level — the 5.1 CONCERNS was a closure-COMPLETENESS gap caught by re-sweeping the architecture's
   enumerated inputs.** The 5.1 reviewer re-swept architecture §77's enumerated cache-key closure inputs
   and found that `prompt-template version` had NO key slot (unlike `model_checkpoint`, which had a stable
   placeholder). This is the same vigilance that caught the no-crash *input-shape* gaps in 3.4/4.2, applied
   one level up — to the COMPLETENESS of a closure rather than the COMPLETENESS of a fixture set. It surfaced
   a future silent-cache-staleness hole (a prompt-template change at Epic-6 6.1 would not move the key) BEFORE
   it could ship, and the fix folded a clean additive placeholder slot now.

4. **The dev-loop's own resumability is robust — two mid-story interruptions, two clean disk-state resumes,
   zero rework.** 5.1's dev session died pre-code and 5.3's died pre-tests (after writing `invalidation.py`
   and flipping status `in-progress`). In both cases the orchestrator resumed from on-disk state: 5.3's resume
   CONFIRMED the already-written `invalidation.py` was complete + ACs-compliant and wrote only the missing
   `test_cache_invalidation.py`. No work was lost or duplicated. This is a useful real-world proof of the same
   resumability discipline APAA itself is built to deliver (FR31/NFR-R2) — the toolchain practices what the
   product preaches.

5. **Reuse-not-fork held at every cache seam — no second serializer, no second hasher, no re-derived key.**
   5.1 COMPOSES the single 1.1 `dumps_bytes` + `compute_content_hash` (grep-confirmed: `hashlib`/`json.dumps`
   not imported in `key.py`). 5.2 CONSUMES `derive_cache_key` (no re-derive) and composes
   `canonical`/`EnvelopeWriter`/`ApaaStorePaths`/`ApaaStoreReader`. 5.3 composes the 5.1 key + 5.2 `MemoStore`
   + 1.3 `ApaaStorePaths` containment + 1.1 envelope. The single-serializer AST gate (rglobs `apaa/**`) stayed
   green and extended-not-forked on every story; `key.py` was unmodified by 5.2/5.3; the frozen Epic-1..4
   contracts show no working-tree diff.

6. **Containment and secret-containment guarantees extended to the new write paths — the no-source/secret
   moat now covers `cache/` AND `decisions/`.** 5.2 extended the 4.4 secret-containment property suite to
   sweep `.apaa/cache/` (TC-SECURITY-17/18, planted-cache-leak CAUGHT); 5.3 extended it to sweep the

## 3. Challenges & Growth Areas

1. **A recurring doc-precision nit appeared across BOTH 5.2 AND 5.3 — a docstring claiming "reuses
   ApaaStoreWriter" while the code inlines a fixed-name-slot byte write.** Both stories carry a Low
   non-blocking finding: the cache `store()` (5.2) and the `RejectionLedger._write` (5.3) inline the write
   (a key-addressed / fixed-name slot, distinct from the content-hash-addressed `ApaaStoreWriter` filename)
   rather than literally calling `ApaaStoreWriter`, yet the docstring/Completion-Notes narrate "via
   ApaaStoreWriter." This is DEFENSIBLE (no serializer/hasher fork — the same 1.1 `canonical`/`EnvelopeWriter`
   are composed; the divergence is only the filename-derivation slot) and was explicitly accepted twice. But
   it is a small accuracy gap that has now repeated, and the §3.4 evidence-immutability principle means an
   inaccurate Completion-Note persists. Worth a note: when a reuse is partial (compose the serializer, inline
   the slot), the docstring should say so precisely rather than overstate "reuses Writer X."

   traversal key vs the "lookup never raises" docstring claim, and `test_lookup_containment_traversal_key_is_a_miss`
   asserts a RAISE despite its "is_a_miss" name.** Negligible real risk (real keys are 64-char sha256 hex, so a
   traversal key is structurally unreachable), but it is a docstring-vs-behavior and a test-name-vs-assertion
   mismatch — the same accuracy-of-narration class as #1. Re-carried as a 🟢 cleanup.

3. **The pre-`review` mandatory-test-existence guard (AI-E2-1 → AI-E3-2 → AI-E4-3) is STILL an in-session
   discipline, not a committed guard — now carried across FOUR epics — and Epic 5's two interruptions

## 4. Key Insights

- **Keystone-adequacy discipline now operates at THREE levels, and Epic 5 proved the design level.** AI-E3-1
  disciplined fixture COVERAGE-CLASSES (depth/equivalence); AI-E4-1 extended it to no-crash INPUT-SHAPES; the
  5.1 CONCERNS shows the same vigilance applied to CLOSURE COMPLETENESS — re-sweeping the architecture's
  enumerated key inputs and finding a missing slot. The unifying lesson: the project's recurring failure
  mode is *an enumeration that omits a member* (a not-deep class, a filesystem input-shape, a closure input),
  and the durable corrective is a CHECKLIST that forces the author/reviewer to enumerate-then-cover the full
  declared set. This is one coherent discipline, not three separate ones.

- **The marquee prior-retro action item, applied to the PREDICTED-risk surface, prevented the PREDICTED
  FAIL — the cleanest L1-E11 outcome yet.** Epic 4's retro explicitly named the cache impure shell
  (`memo_store.py`) as "exactly the surface that produced the 4.2 FAIL" and prescribed the AI-E4-1
  input-shape checklist for 5.2/5.3. It was applied, and 5.2/5.3 passed iter-1 with the full no-crash matrix
  fixtured. The "too-weak keystone test" class — the only FAIL in BOTH of the two prior epics — did not recur.
  This is the action-item-as-deliverable loop converting a two-epic recurring FAIL into a non-event.

- **The dev-loop's resumability is a real, observed property — the orchestrator resumes mid-story from disk
  without rework.** Two interruptions, two clean resumes. The 5.3 resume is especially instructive: it
  re-read the on-disk state, CONFIRMED the already-written product code, and completed only the missing test
  step. This is exactly the FR31/NFR-R2 resumability APAA is built to deliver, observed in the toolchain that
  builds APAA — encouraging for the Epic-7 dogfood (a long, partitionable, interruptible run).

- **Tier-B review value is COMPLETENESS re-sweeping, not line-level bug hunting.** Across Epics 4–5 the
  highest-value reviewer activities have been: reproduce-then-revert a no-crash edge (3.4/4.2), re-render and
  forbidden-phrase-scan a verdict (4.1), and re-sweep an architecture-enumerated closure (5.1). All three are
  COMPLETENESS audits of a declared set. As Epics 6–7 add the Prosecutor, precision harness, and dogfood
  (more "prove the spine" work over frozen producers), this is the review posture to keep.

- **Defer-inflow remains converged (net ≈ 0 for a second consecutive epic) and the carried-debt picture is
  dominated by ONE dated item.** DF-5-1-A opened and closed same-epic; no other new defer was filed. The
  carried register is now effectively: 🟡 **DF-1-7-B (interim Python deep over-grading)** — now ONE EPIC AWAY
