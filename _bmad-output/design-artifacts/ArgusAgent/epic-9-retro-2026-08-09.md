## 3. Challenges & Growth Areas

1. **The story immediately after the honesty epic republished an unmeasured figure — in the consumer-facing release contract — and the discipline that was supposed to prevent it did not apply to the failure that occurred.** This is the finding worth carrying above every other, because it is *not* a repeat of Epic 8's diagnosis; it is a **different failure mode wearing the same clothes.**

   What happened, measured: three consumer-facing sites (`CHANGELOG.md:110`, `README.md:92`, the `DF-9-2-A` body in `deferred-work.md`) published *"65 of the 69 shipped modules import"* and named **four** broken modules. Re-measured by the reviewer: **66 of 71 import, five fail** — and the fifth, `argus/precision/replay_harness.py`, is *the module that contains the offending import*. The committed pin `_NOT_IMPORTABLE_FROM_DISTRIBUTION` (`tests/test_release_preflight.py:260-268`) listed **five all along**, and the same delta stated the correct denominator **five lines away** at `CHANGELOG.md:105` (*"the wheel holds 71 modules"*). The dev then found **two further sites** the review had not named — Completion Note 7 and the header comment of `test_release_preflight.py` itself — so the wrong figure was published at **five** places.

   **Why the discipline did not transfer.** Epic 8 diagnosed the *inherited belief*: a figure the author thought was already established, copied from their own context. The counter-discipline it prescribed — independent re-derivation — works on that. This was not that. The `65 / 69 / four` figure was, on the evidence, **measured correctly at a moment when it was true** and then invalidated **by the same story's own later work**: AC8's split took the tree from 69 modules to 71 and added two modules to the broken set. Independent re-derivation *did* catch it — that is exactly what the reviewer did — but only at the review gate, after the number had been written into the release contract. Neither AC13 (*"do not restate a figure you did not re-derive"*) nor the dev's re-derivation practice covers **"re-measure the figures your own subsequent commits falsified."**

   **What did work, and it is the rule to carry:** the number was right in the one place that was **pinned** and wrong in all five places where it was **prose**. The single-source-of-truth mechanism this project already uses for code (AR7 reuse-not-fork; `argus/__init__.py:56-58`'s *"never hardcode this literal at call sites"*) had no analogue for documents. **A prose copy of a pinned figure is a fork, and forks rot inside a single story.**

   The same class produced **R2** on a different surface: `CHANGELOG.md` asserted *"The distribution is therefore **resolvable by the VCS pin below**"* — an affirmative capability claim for a tag that does not exist, exercised by nobody — while `README.md:36-38` said *"Until a tag is pushed, the resolvable reference is the repository itself:"* and then handed the reader a **tag-pinned** command. The sentence and the code block it introduced stated different things. Both were fixed, adjacently and in both documents. But the honest reading of an honesty epic's successor failing this way at its first opportunity is: **the discipline was applied conscientiously to the classes that had already been named, and the classes that had not been named went straight through.**

2. **A real supply-chain security defect was introduced by new code and caught only at review — and this repository had no earlier gate that could have caught it, because the defect class arrived with the epic.** `.github/workflows/release.yml` interpolated `${{ inputs.tag || github.ref_name }}` and `${{ steps.resolve.outputs.tag }}` **into `run:` script bodies** on a job holding `contents: write` and `github.token`. The tag-push trigger is constrained by the `v[0-9]+.[0-9]+.[0-9]+` filter; **`workflow_dispatch.inputs.tag` is free-form**, so a crafted dispatch executes arbitrary shell in a job that can write to the repository. Three third-party actions were additionally pinned to **mutable major tags** on that same job.

   Asked honestly — *was there an earlier gate?* — the answer is no, and the reason is instructive:
   - `audit-ci.yml` runs **bandit**, which scans Python. The defect is in YAML.
   - **Argus itself audits Python.** The tool this repository builds could not have found this in its own repository.
   - The story applied AI-E8-6 diligently and built **four** enumerated spaces — the E1–E6 release edge cases, the seven release surfaces, the AC15 fence list, the version surface. The injection sat outside **every one of them**, because those spaces enumerate *what a release must check*, *which documents may over-claim*, *which files may not be touched* and *where a version may appear*. **None of them enumerates "what a privileged workflow file is."**

   So: **Epic 9 is the first epic in which this repository acquired CI/CD supply-chain surface, and it went in with zero gates for that class.** The fix built the missing one — `TC-ArgusAgent-RELEASE-001-17` extracts every `run:` block body and fails on **any** interpolation, rather than pattern-matching the cases someone thought of, which is the correct shape — but it covers exactly one file. The residue is `DF-9-2-D`: the **pre-existing** instance at `action.yml:127` (`if [ "${{ inputs.strict }}" = "true" ]`, a consumer-supplied composite-action input expanded into shell source) is still open, still unowned, and sits in the file a consumer actually adopts.

3. **The distribution ships with a known, disclosed, unowned import defect — `DF-9-2-A` — and the residual risk deserves plain words rather than a severity glyph.** Measured from the built wheel with this repository removed from `sys.path`, one clean subprocess per module, independently re-derived by the reviewer through the committed `_modules_reaching` AST walk:

   | | |
   |---|---|
   | Modules in the wheel | **71** (+ 5 `dist-info` entries = 76; 0 non-`.py`) |
   | Import cleanly | **66** |
   | Do **not** import | **5** — `argus/precision/__init__.py`, `argus/precision/replay_harness.py`, `argus/dogfood/proof_types.py`, `argus/dogfood/proof_render.py`, `argus/dogfood/proof_run.py` |
   | Failure | `ModuleNotFoundError: No module named '_registry'` |
   | Single cause | `argus/precision/replay_harness.py:87-90` inserts `<repo>/tests/cartridges` onto `sys.path` and imports `_registry` unconditionally; `tests/` is not in the distribution and should not be. The other four reach that import transitively (`precision/__init__.py` re-exports it; `proof_types.py:33` imports `MatchKey` from it; `proof_render.py` imports `proof_types`) |

## 4. Key Insights

- **A retrospective changes something only when a human converts it into acceptance criteria before the next story is written.** Two epics of evidence now point one way. AI-E8-4 went through *retro → operator ruling → SM re-context → ACs → closing evidence* and produced eleven of 9.2's seventeen acceptance criteria and four closed ledger entries. AI-E8-2, -5, -8, -9 and -10 were framed as *"someone should build/record/decide"* and are, without exception, in the same state today as when they were written. Epic 8 said this about the Epic-7 handoff and then reproduced it with its own items. **The generalisable rule: a retrospective's only load-bearing output is the item the operator rules on before contexting; the rest is a document about intentions.**

- **There are two distinct ways a published number goes wrong, and this project has now found both — and only one of them is caught by independent re-derivation.** Epic 8 found the **inherited belief**: a figure the author believed was already established, whose check and belief shared an origin. Epic 9 found the **self-invalidated measurement**: `65 of 69` was, on the evidence, correct when taken and was falsified by the *same story's* later commit, which took the tree to 71 modules and added two to the broken set. An independent party measuring at the end gets the right answer — the reviewer did — but only after the wrong number reached the consumer-facing contract. The mechanism that held throughout was **single-sourcing**: the committed pin `_NOT_IMPORTABLE_FROM_DISTRIBUTION` was correct at all times while five prose copies were wrong. **Prose that restates a pinned figure is a fork of that figure, and a fork can rot inside a single story.** The successor to AI-E8-6 is: *where a document states a number that a test also pins, either the document cites the pin or a test asserts the document.*

- **Enumerating a space protects you inside that space and nowhere else — and nobody enumerates a space they have not noticed they created.** 9.2 built four fail-on-unenumerated guards, all correct, all discharged. The script injection sat outside every one, because a repository that had never held a privileged workflow had never needed to ask *"what is the space of things a `run:` body may contain?"* The fix built exactly that guard, in exactly the right shape (extract every body, fail on any interpolation) — after the defect. **When a new artifact class enters a repository — a publishing workflow, a signed artifact, a distributed package — it brings a space with it, and the first story to introduce it is the story least equipped to notice.** The cheap countermeasure is a story-authoring question rather than a test: *what class of file is new here, and what is its failure mode?*

- **A deferral addressed to a trigger executes; a deferral addressed to a condition waits forever.** `DF-8-5-D` said *"the first story that edits `proof_run.py` for any reason"* — a story edited it, and the extraction landed with its cascade pre-simulated. `DF-8-2-A`/`-3-A`/`-3-C` said *"gates on the `pipeline.py` extraction"* — nine epics, no story, no movement, and the module now sits at 1199/1200. Same register, same severity conventions, same authors; **the only structural difference is that one names an event that will happen and the other names a state that must first be produced.** And when the plan ends, both collapse to the same thing: a `target_story` that resolves to nothing.

- **"Prepared, not executed" is an honest state, a genuine achievement, and not a delivery — and an honesty project has to be able to hold all three of those at once.** The workflow is committed, SHA-pinned, injection-hardened, permission-minimal, secret-free, and backed by 19 tests. The artifact is built, installed into a clean environment, executed from outside the repository, and its contents recorded verbatim. Every document says the tag does not exist, adjacent to every command that needs it. **And a consumer still cannot resolve `argus-agent` today.** Epic 8 deleted a false accusation from a tool that must not cry wolf; Epic 9's equivalent temptation is to score a correctly-described non-delivery as a delivery, and the correct reading is that the epic delivered *everything it could reach* and stopped precisely at the boundary it was given.

- **The tool cannot audit the class of defect it just acquired, and that is worth knowing about the product, not only about the project.** Argus audits Python. Epic 9 added a GitHub Actions workflow, a composite action arm, and a release script, and the one genuine security defect of the epic lived in the YAML. This is not a flaw in Epic 9's execution — it is a scope fact about Argus that the epic surfaced by walking into it. Any future claim about what an Argus audit covers should be read against it.
