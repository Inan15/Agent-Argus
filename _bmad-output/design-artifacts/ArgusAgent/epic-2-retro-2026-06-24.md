## 2. What Went Well (Successes)

1. **Zero review FAILs across all six stories — and the one Epic-1 failure mode was the thing Epic 2
   pre-empted.** Epic 1 had exactly one review FAIL (1.4, the non-ASCII `git ls-files`/subprocess-decode
   boundary). Epic 2's headline outcome is that the **highest-risk story by the same risk class — 2.6, the
   first impure subprocess/tool shell since 1.4 — passed iteration 1**, specifically because the Epic-1
   action item AI-E1-1 was applied there proactively (see §5). This is the L1-E11 loop paying off in one epic.

2. **The determinism / single-serializer / Fraction-not-float / advisory-moat discipline held across all
   six stories with zero erosion.** Every story routed through the single `apaa/store/canonical.py`
   serializer (the committed single-serializer AST gate stayed green at every step — verified per-story in
   2.1–2.6), stored ratios as exact `Fraction` (2.1 deep-%, 2.2 deep-%/aggregate, 2.5 entropy via a 1e-6
   grid — never a float leaf), and kept the false-accusation moat intact: every new detector (2.5 secret,
   2.6 tool-failure) emits `advisory=True` / `depth_supported=None`, so it is structurally **not
   verdict-eligible** and the frozen 1.6 gate was never modified. Determinism was re-proven order-independent
   per story (2.4 reversed-input partitioning, 2.6 input-order-independent classifier).

3. **The three security keystones were each verified non-bypassable, by independent reasoning, not by
   convention.**
   - **2.4 work-manifest permission boundary (NFR-S4)** — `is_in_scope` is EXACT normalized-membership in a
     `frozenset`, never a prefix/substring check; sibling-prefix (`auth/secrets_extra.py` vs `auth/secrets`),
     truncation, bare-dir, `../` traversal, absolute/UNC/drive-letter, and cross-manifest non-ASCII queries
     were all rejected before compare. Off-scope read → `PartitionScopeError`, structurally impossible.
   - **2.5 secret containment (NFR-S2/FR28)** — there is **no `value` field structurally** on any persisted
     model; the raw secret lives only on a transient `__slots__ _Match`, computed → masked → discarded.
     `recording_id` is value-independent. The mandatory containment suite proved planted ASCII + Cyrillic
     sentinels ABSENT from every persisted `.apaa/` byte AND in-memory finding bytes, while findings ARE
     emitted (redaction ≠ silent suppression).
   - **2.6 tool-output redaction (NFR-S1)** — neither outcome model carries any raw-stdout/stderr field; the
     reason is a closed token; the radon invoker drops the raw error at the boundary. Hostile-tool-output
     sentinels (ASCII + Cyrillic) confirmed absent from raw serialized bytes and the full persisted tree.

4. **"Tool-failure-as-finding" was proven, not promised (2.6, FR14/NFR-R1).** Every injected failure mode
   (unavailable / crashed / timed-out / unparseable) maps to a `tool_failure` Recording + a `SKIPPED`
   downgrade + a sanitized-token `DegradedCondition`; a raising or misbehaving invoker is caught as
   `CRASHED` and never propagates; a malformed arg raises a typed `ToolRunnerError(ValueError)` whose message
   names the argument only. No bare `except: pass`, no `print()`, no `subprocess`/`shell=True` (V1 = the
   radon **library** API behind an injected `tool_invoker` seam — the safest possible choice for the boundary
   that bit 1.4).

5. **Seam-not-fork discipline (extend, never re-derive) held at every reuse point.** 2.3 fed a computed
   boolean into the UNCHANGED 1.6 gate; 2.6 drove the REAL `evaluate_verdict` over a synthetic ledger to
   prove `tool_scanned_only` is denominator-only (FR8) rather than reimplementing the math; the
   `_MODULES_UNDER_GUARD` no-web-imports gate and the single-serializer gate were **extended, never forked**,
   on every story. Frozen 1.1/1.2/1.5/1.6 contracts show no working-tree diff across the epic.

6. **Anti-gaming was treated as a first-class property, not an afterthought.** 2.1 made criticality
   content-derived (rename-gaming defeated: `utils_misc.py` with auth content → CRITICAL; `auth_guard.py`
   doing arithmetic → NORMAL; non-ASCII `café_guard` casefold → CRITICAL). 2.3 proved the operator
   `--exclude-critical` lever can only make the gate STRICTER or is audited via persisted
   `excluded_critical_paths` provenance — never a silent bypass.

## 3. Challenges & Growth Areas

1. **The 2.1 `assess_criticality` bare-substring matcher over-flags benign tokens (DF-2-3-A 🟢).** It matches
   substrings like `tokenize`, a `tokens` param, or "retry policy" as criticality signals. The direction is
   SAFE (over-flag → more scrutiny) and the operator `--exclude-critical` override is the V1 correction lever,
   so it is non-blocking — but it is precision debt that should be tightened to identifier-boundary /
   import-name / dotted-reference matching in a precision pass. This is the only correctness-adjacent carried
   item that originated in Epic 2.

2. **Persisted run-state records operator designation INTENT, not the computed critical set (DF-2-3-B 🟢).**
   The `.apaa/` run-state persists `request.to_provenance_payload()` (raw `critical_paths` /
   `excluded_critical_paths`) but NOT the computed `CriticalSubsystemSet` (final paths + per-path `origins` +
   `designated_but_unmatched`). The exclusion lever IS auditable (intent is recorded), and the
   negative-assurance narration of which critical subsystems were/weren't covered is explicitly Epic-4 Story
   4.1 scope — so this is in-scope-deferred, owned by 4.1, not a defect.

3. **The two session-limit / timeout interruptions during 2.6 exposed a process gap: a worker set
   `status=review` BEFORE writing the mandatory test suite.** The story ultimately landed correct
   (532 passed, the AI-E1-1 suite present and non-vacuous, review PASS iter-1), and the code-review gate
   caught nothing missing because by review time the suite existed — but the **premature status flip is a
   real risk surface**: had the interruption been terminal, an under-tested story could have sat at `review`
   advertising readiness it did not yet have. There is currently **no engineered guard that catches a
   `*→review` transition whose mandatory test files do not yet exist**. Per the rule-of-three
   guard-promotion policy (CLAUDE.md §9.2), this is occurrence 1 of this specific failure mode for APAA;
   it should be watched, and a cheap pre-`review` test-existence assertion is a strong rule-of-three / even
   occurrence-2 promotion candidate given the cost asymmetry. (Note: the Dev Agent Record template fields in
   2.6 were left as unfilled placeholders — consistent with the interrupted authoring — which is a minor
   evidence-completeness nit, not a correctness gap.)

4. **Two minor DRY/scope-dormancy cleanups in 2.6 (both 🟢 Low, accepted).** (a) `ToolRunOutcome` is defined
   + exported but UNUSED (`ToolInvocation` is the working equivalent; AC4 permits "or equivalent", both carry
   the no-raw-field guarantee) — collapse to one model or document the split in a cleanup pass. (b) The
   pipeline-level `tool_failure` surface is DORMANT for already-graded files (the `already_graded`
   short-circuit runs before the outcome branch, and V1 depth-grades every indexed Python file) — this
   MATCHES the locked AC5 no-double-count rule and the detector contract is fully unit-tested, so it is an
   accepted V1 scope limitation. Plus two more Low cleanups across 2.1/2.2/2.5 (substring over-match doc,
   markdown-cell robustness, pattern_id granularity erased on persistence) — all safe-direction, all
   non-blocking.

## 4. Key Insights

- **Applying a prior retro's action item AT the exact boundary it was written for converts a known failure
  class into a non-event.** AI-E1-1 (adversarial non-ASCII + locale + failure-injection fixtures for
  impure-shell parsers) was authored in response to Epic 1's only FAIL (1.4). It was applied first in 2.6 —
  the structurally identical risk surface — and 2.6 passed iteration 1. The lesson Epic 1 learned the hard
  way did not recur. This is the strongest single piece of evidence for the L1-E11 operating model (§9.1)
  in APAA so far.
- **Structural impossibility beats runtime checking for security keystones.** All three keystones won by
  REMOVING the field that could leak (no `value` on persisted models, no raw-output field on tool outcomes)
  or by EXACT-membership rather than prefix matching — i.e. the leak/escape is unrepresentable, not merely
  guarded. A removed field cannot be accidentally populated by a later story.
- **The determinism spine and the false-accusation moat are now load-bearing across two epics with zero
  erosion** — the two properties every later epic folds over are holding as structural gates, not per-story
  vigilance, exactly as the Epic-1 retro predicted.
- **The gap that remains is in the PROCESS layer, not the code layer.** Epic 2's code quality was uniformly
  high (0 FAILs); the one genuinely new risk it surfaced is the premature `status=review` flip under session
  interruption — a tooling/process failure mode, the same class (one level up) that L5-E11 / L8-E10 warn
  about. The fix, if promoted, must be a committed guard, not a reviewer-vigilance promise.
- **Defer inflow is converging (5 → 2).** Both Epic-2 defers are 🟢 and one is already owned by a scheduled
  story (4.1). New debt is being created slower than Epic 1 — a healthy backlog-convergence signal (§9.3).
