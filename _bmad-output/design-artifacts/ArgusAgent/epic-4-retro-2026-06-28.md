## 3. Challenges & Growth Areas

1. **The epic's only review FAIL (4.2) was an uncaught `OSError` escaping the no-crash keystone — the SAME
   class as the Epic-3 3.4 FAIL: a keystone test that did not cover its own keystone bug.** The 4.2
   referential-integrity lint's FR26/AC6/AR10 contract is "a broken reference is a TYPED finding, NEVER a
   raise." The enumerate-and-read shell caught only `(StoreIntegrityError, CanonicalSerializationError,
   ValidationError, FileNotFoundError)`, but `_list_locators` globs `*.json` which ALSO matches
   directories — so a directory (or permission-denied entry) named `<sha>.json` under `.apaa/` (an
   interrupted/partial write — the EXACT corruption this lint exists to catch) raised `IsADirectoryError`
   (POSIX) / `PermissionError` (Windows), both `OSError`-not-`FileNotFoundError`, escaping the lint. The
   AC6 test set (tamper / corrupt-bytes / unknown-field) did not exercise this class.
   - **What caught it:** the reviewer reproduced it LIVE — planting `state/evil.json` as a *directory* on a
     real `vacuous_basic` run crashed with `PermissionError` instead of returning an `unreadable_artifact`
     finding. The fix broadened the shell catch to `OSError` (subsumes `IsADirectoryError` /
     `PermissionError` / raced-delete `FileNotFoundError`) while keeping `StoreIntegrityError` /
     `ValidationError` tokenized distinctly and `WorkspaceContainmentError` (a `ValueError`, not `OSError`)
     still propagating — verified RED-then-green via a durable planted-directory keystone test
     (TC-APAA-STORE-001-108).
   - **Root-cause class:** a no-crash keystone whose fixtures exercise the *content*-corruption cases the
     author imagined but not the *filesystem-shape* cases (a non-file at a path the glob admits). This is the
     SECOND consecutive epic whose only FAIL is a too-weak keystone test (3.4 masked dropped-coverage; 4.2
     missed a no-crash edge). See §4 for the escalation decision.

2. **The pre-`review` test-existence guard (AI-E2-1 → AI-E3-2) is STILL an in-session discipline, not a
   committed guard — now carried across three epics.** Every Epic-4 story line records "AI-E3-2/E2-1
   test-existence gate honored before review flip," but there is no committed `scripts/`-style check that
   would fail a `*→review` flip whose mandatory test files are missing. Epic 4 had zero session interruptions
   so the risk did not bite this epic, but the gap is unchanged. 4.4 (the first CI-blocking APAA suite) was
   the prior retro's nominated moment to also land this committed check — it was NOT landed (4.4 was correctly
   scope-fenced to the secret-containment suite per its create-story plan). The carry continues.

3. **The defer-register consolidation (AI-E1-3 → AI-E2-3 → AI-E3-3) finally became fully countable from one
   place — but by attrition, not by an explicit back-fill.** Defer-inflow this epic was countable from the
   central `deferred-work.md` alone (both carried defers have append-only closure/left-open notes there, and
   no new defers were filed), which is the convergence the prior retros wanted. However, the explicit
   back-fill of the older story-line-only defers (DF-3-1-A, DF-2-3-A, Epic-1 DF-1-4-A / DF-1-7-A / DF-1-7-B)
   that AI-E3-3 asked for was NOT done — they still live only in story lines. With inflow at zero this is now
   cheap cleanup rather than an active counting risk; re-carried at lower priority.

4. **Tier-B story character shifted from "build the spine" to "harden + prove the spine," and the FAIL
   profile shifted with it.** Epics 1–3 (Tier-A) built net-new mechanisms (serializer, ledger, gate, budget,
   resume) and their FAILs were in net-new code reconciling with state (3.4 resume). Epic 4 (first Tier-B) is
   dominated by *wrappers, lints, exports, and property suites over already-shipped producers* — 4.4 was a
   pure verify-and-lock. The one FAIL (4.2) was still in the only genuinely net-new mechanism (the lint's
   impure enumerate-and-read shell), consistent with the standing pattern: **risk concentrates in the impure
   shell that touches the filesystem, not in the pure core.** This is a useful predictor for Epics 5–7.

## 4. Key Insights

- **"Too-weak keystone test" is now a TWO-EPIC recurring failure mode (3.4 masked dropped-coverage; 4.2
  missed a no-crash filesystem-shape edge) — it has reached the §9.2 rule-of-three promotion threshold (now
  occurrence 2, trending to 3) and warrants a CHECKLIST promotion now, with an engineered guard scoped for
  Epic 6's cartridge harness.** AI-E3-1 (the keystone-fixture-adequacy *practice*) was applied and demonstrably
  worked for the keystones the author thought to fixture — 4.1/4.3/4.4 all went RED-then-green correctly. The
  4.2 FAIL shows the practice's blind spot: it disciplines the *coverage/depth classes* an equivalence
  preserves, but it does not prompt the author to enumerate the *failure-input shapes* a no-crash contract
  must absorb (here: a non-file at a glob-admitted path). The corrective is a small extension of the practice
  into a **no-crash-keystone input-shape checklist** (for any "X degrades to a finding, never raises" keystone,
  the fixture set MUST include: a missing entry, a non-file entry at an admitted path, a permission-denied
  entry, a corrupt-bytes entry, an unknown-field entry — each demonstrated RED). Because review caught BOTH
  recurrences only by *reproduce-then-revert*, this is precisely the §9.2 class that should be mechanized: the
  recommendation is to land the checklist now (AI-E4-1) and scope a fixture-shape-coverage assertion into the
  Epic-6 cartridge harness (AI-E4-2). Promotion at occurrence 2 is justified by the cost asymmetry — both
  FAILs would have shipped a false guarantee absent a vigilant reviewer.

- **Reproduce-then-revert remains the single control that catches a too-weak keystone — and it caught the
  FAIL in BOTH Tier-A and Tier-B epics.** No static read of a green keystone test surfaced either bug; only an
  independent reproduction (3.4: reproduce the divergence; 4.2: plant a real directory and watch it crash)
  did. Until the AI-E4-1/AI-E4-2 guards exist, this reviewer habit IS the control and must be preserved
  explicitly in the code-review checklist.

- **A prior retro's marquee action item, applied as written, pays off immediately AND reveals its own next
  edge.** AI-E3-1 (keystone-fixture adequacy) was the direct response to the 3.4 FAIL; in Epic 4 it cleanly
  caught the keystones it covered (4.1/4.3/4.4 RED-then-green) and, by its absence on filesystem-shape inputs,
  precisely localized the next FAIL (4.2). This is the L1-E11 loop working: the action item didn't just prevent
  a recurrence of the *same* bug, it sharpened the team's model of the failure *class* one level deeper.

- **Convergence is real and measurable: zero new defers, two carried defers closed, four-epic clean
  determinism/security-gate streak.** The defer-inflow trajectory (5 → 2 → 2 → 0) plus the closure of DF-2-3-B
  and the DF-1-3-A integrity gap means Epic 4 RETIRED more debt than it created — the first net-negative-debt
  epic. The structural gates (single-serializer, no-web-imports, file-size, and now the CI-blocking secret
  suite) held green across every story for the fourth consecutive epic.

- **Tier-B is "prove it," and the proof is durable CI, not a story-local assertion.** The most valuable Epic-4
  artifact is arguably 4.4 — a CI-blocking property suite that survives a fresh clone and backstops the WHOLE
  pipeline, reusing the existing merge-blocking job (no new CI surface). This is the L5-E11 durability lesson
  applied: the security guarantee now lives in a committed gate, not in per-story reviewer attention.
